# 보안 규칙

> 출처: 개발 보안 가이드 v1(2026.08.13), 소프트웨어 개발보안 가이드(2021.11 개정) 기반.
> 코드 작성 시 아래 항목에 해당하면 반드시 적용한다. 항목 뒤 괄호는 원본 가이드 코드(S1~S10).

## DB 접근 (S1)
- 외부 입력을 SQL 문자열에 직접 결합하지 않는다. JPA/MyBatis의 파라미터 바인딩만 사용한다.
- MyBatis 사용 시 `${}` 대신 `#{}` 를 사용한다.
- 동적 정렬·필터 조건의 가변 부분(컬럼명 등)은 화이트리스트로만 허용한다.

## 사용자 입력 / 출력 (S2)
- 모든 입력값은 서버에서 검증한다(`@Valid`, Bean Validation). 클라이언트 검증만 믿지 않는다.
- 사용자 입력이 그대로 화면(다른 API 응답)에 노출되는 지점은 출력 인코딩을 적용한다.
- 게시글·댓글·자유입력 텍스트가 포함된 응답 필드는 특히 주의한다.

## 인증 (S3)
- 인증은 반드시 서버에서 수행한다.
- 비밀번호는 솔트 포함 해시(BCrypt 등)로 저장한다. 평문·단순 해시 저장 금지.
- 로그인 실패 횟수를 제한하고 초과 시 잠금·추가 인증을 적용한다.

## 인가 / 권한 (S4)
- 중요 기능(수정·삭제·타인 리소스 접근 가능 지점)마다 서버에서 권한을 검증한다.
- 식별자(id) 파라미터만으로 접근을 허용하지 않는다 — 반드시 **소유권**(본인 것인지)을 함께 검증한다.
- 클라이언트가 보낸 역할·권한 값을 신뢰하지 않는다. 서버 세션/토큰 기준으로만 판단한다.

## 파일 업로드 (S5)
- 확장자를 화이트리스트로 검증한다(대소문자 포함).
- 파일 크기를 제한한다.
- 저장 파일명은 추측 불가한 값(UUID 등)으로 변경하고, 원본 확장자를 그대로 실행 가능한 경로에 두지 않는다.

## 파일 다운로드 (S6)
- 다운로드 대상은 파라미터로 받은 경로를 직접 쓰지 않고, 식별자→서버 매핑으로만 지정한다.
- 부득이 파일명을 받는다면 `/`, `\`, `..` 등 경로순회 문자를 필터링한다.
- 다운로드 전 접근 권한을 검증한다.

## 외부 API 연동 (S7)
- 서버가 요청할 URL을 사용자 입력으로 직접 받지 않는다. 화이트리스트로 제한한다.
- 외부 응답값은 검증 후 사용한다(신뢰하지 않음).
- API Key·시크릿은 코드에 하드코딩하지 않고 설정/환경변수로 분리한다.

## 개인정보 / 중요정보 (S9)
- 개인정보·금융정보·비밀번호는 저장·전송 시 암호화한다.
- 전송은 HTTPS 등 보안 채널만 사용한다.
- 코드·설정·주석에 비밀번호·키·개인정보를 남기지 않는다.

## 오류 처리 / 로깅 (S10)
- 사용자에게는 일반화된 오류 메시지만 노출한다. 스택트레이스·쿼리·내부 경로를 그대로 보여주지 않는다.
- 예외를 흘려보내지 않고 내부에서 처리한다 (`error-handling.md` 참고).
- 로그에 비밀번호·토큰·개인정보를 남기지 않는다.

## 관리자 기능 (S8, 해당 시)
- 관리자 권한은 서버에서 검증한다.
- 중요 작업(승인/반려 등)은 로그를 남긴다.
